# Part V — Characters and byte-pair encoding

Run `python -m part_5_tokenizer.tokenizer` from the repository root.
`results/examples.json` records English, Japanese, accented letters and emoji,
their IDs and exact reconstructions. It also records the character tokenizer's
explicit failure on unseen characters.

The character tokenizer maps training characters to IDs. BPE begins with all
256 bytes, counts adjacent pairs and replaces the most frequent repeated pair
with a new token. Encoding replays learned merges in order. Decoding concatenates
the token bytes before decoding UTF-8. `results/tokenizer.json` saves the rules.

Unseen text remains encodable through bytes. Japanese can require more tokens
when training favors English, and a byte is not necessarily a whole character.
Arbitrary generated byte sequences may fail UTF-8 decoding; round trips of valid
encoded text remain lossless. This tiny example may merge a repeated sentence
into one token, illustrating corpus dependence rather than a production vocabulary.
